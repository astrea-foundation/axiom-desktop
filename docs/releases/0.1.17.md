# Axiom 0.1.17

AstreaAI is available through the normal Axiom account, with the uncensored
Qwen3.8 model, image understanding, tools and image generation. Thinking stays on.
The workload has a 32,768-token context and a 4,096-token output limit. Image
generation defaults to 1536 by 1536 and accepts up to five ordered references.

Installers include a standalone, pinned attestation verifier for each supported
platform. Customers do not install Python or provide a local environment file.
Inference still requires fresh CPU, GPU and workload evidence, accepted recipient
keys and authenticated response completion. Public account configuration binds
the production account service, issuer and immutable chat and image prices;
private issuer credentials stay on the account-service host.

Billing uses account-owned reservations and authenticated worker usage. Replayed
receipts cannot create another debit. Busy requests return bounded capacity
errors and inference is never automatically replayed after a failure. Desktop
keeps waiting for native credentials during startup and reconnects.
Chat request identities are preserved through the account reservation, encrypted
execution and authenticated receipt so the native accounting guard can match
usage to the originating request.

Installer assembly resolves the bundled verifier from the workspace root even
when Electron changes directories. Both relative and absolute bundle paths are
supported, with the existing inventory, architecture and signature checks.

This release also updates the Markdown parser and executor dependency to clear
the current security advisory and yanked-version checks. Existing account-scoped
storage remains compatible. Desktop and its bundled AxiomCLI share version
**0.1.17**; installer qualification and publication follow the
[release procedure](../releasing.md).
