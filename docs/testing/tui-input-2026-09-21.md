## Findings and fixes

| Finding | Correction and regression coverage |
|---|---|
| Slash commands entered while running became model steering | Parse commands locally in every task state. Usage, help, retained security evidence and appearance remain available; session-changing commands retain the draft and require stopping first. PTY coverage opens usage, closes it without cancellation and rejects logout while the original task is still running. |
| Uppercase characters vanished during active work | Accept ordinary and Shift-modified text consistently; do not insert Control/Alt shortcuts as characters. A PTY round trip persists the exact mixed-case draft. |
| Bracketed paste was dropped during active work | Accept multiline paste in the visible composer, including steering drafts. PTY coverage persists the mixed-case multiline result after cancellation. |
| Picker paste changed the hidden composer | Route paste to the visible model/resume/delete filter, transcript search, question answer or export filename. Ignore paste in non-editable overlays and deletion confirmation. PTY coverage selects a pasted model filter and verifies that the next prompt is uncontaminated. |
| Signed-out production TUI exited before showing login | Do not call catalog-validating model setters before authentication. Reconcile the account preferences against the catalog after login, before persisting the new session. A production-runner PTY test reaches login without a credential or account database; a local bootstrap test verifies preference reconciliation. |
| An inspector could obscure an incoming agent approval/question | Render foreground interactions last, matching keyboard priority. Escape on the visible interaction still cancels the task. Render tests cover both approval and question cards above the usage inspector. |
| A live tool approval consumed ordinary steering letters as `y`/`n` decisions | Require explicit `Ctrl+Y`/`Ctrl+N` decisions and `Ctrl+G`/`Ctrl+P` for offered session grants. Unit and PTY tests reject ordinary, Shift-modified, pasted, Enter and the composer's `Ctrl+E` editing input as decisions. Live retest confirmed `yNeP` leaves the card pending and `Ctrl+Y` permits the inspected operation. |
| The signed-out PTY test could reuse the developer's real native credential | Isolate the API/auth origin as well as XDG paths. A fresh loopback HTTPS listener asserts that signed-out startup makes no service requests; no production credential or keyring entry is removed. |
| The security inspector hid the reason when attestation failed before producing evidence | Retain a sanitized, process-local failure diagnostic and render it in every inspector view. Clear it on fresh verification and model/account reset. Unit/render coverage and a live Qwen rejection confirm the reason remains visible independently of the status line. |
| Resume called normal agent edits a warning and persisted another copy every time | Stop generating the synthetic workspace-change warning and skip legacy copies during TUI replay without erasing the journal. Regression tests retain task edit history and real warnings, cover repeated resume, and preserve interrupted-turn/tool recovery warnings. |

## Remaining provider/release limits

Selecting `qwen-3-6-35b` (Qwen 3.6) repeatedly failed preflight with the message
that the provider's Intel TDX environment is **OutOfDate** and requires security
updates. That native diagnostic maps to the deployed backend's
`PROVIDER_TDX_OUT_OF_DATE` error. The NEAR verifier uses that code for
`OutOfDate` or `OutOfDateConfigurationNeeded`; the public error alone does not
identify the missing update or advisory. No Qwen inference was sent. The patched
inspector displayed the reason, and switching back to GLM restored current
verified proof. This is an unresolved provider-environment gate, not a reason to
relax client verification. Intel defines these statuses as an outdated platform
software/firmware security level (with additional configuration needed in the
latter case): [Intel TCB status reference](https://portal.trustauthority.intel.com/eat_profile.html#attester_tcb_status).

This run establishes live NEAR agent behavior and the Qwen fail-closed path; it
does not establish successful live inference for every registered provider,
macOS/Windows acceptance, installers or a production release.
