# TUI input and startup validation — 2026-09-21

## Scope

Native branch `fix/tui-provider-neutral`, based on `0d6622c`, with the fixes
accompanying this report. Linux, Alacritty on the shared 1280×800 virtual desktop;
automated terminal tests also resize from 60×14 to 100×30 cells. The native
application targets `https://api.axiom.stream` and uses the normal hosted browser
authorization flow. No backend code, deployment, credential policy or provider
verification was changed.

## Findings and fixes

| Finding | Correction and regression coverage |
|---|---|
| Slash commands entered while running became model steering | Parse commands locally in every task state. Usage, help, retained security evidence and appearance remain available; session-changing commands retain the draft and require stopping first. PTY coverage opens usage, closes it without cancellation and rejects logout while the original task is still running. |
| Uppercase characters vanished during active work | Accept ordinary and Shift-modified text consistently; do not insert Control/Alt shortcuts as characters. A PTY round trip persists the exact mixed-case draft. |
| Bracketed paste was dropped during active work | Accept multiline paste in the visible composer, including steering drafts. PTY coverage persists the mixed-case multiline result after cancellation. |
| Picker paste changed the hidden composer | Route paste to the visible model/resume/delete filter, transcript search, question answer or export filename. Ignore paste in non-editable overlays and deletion confirmation. PTY coverage selects a pasted model filter and verifies that the next prompt is uncontaminated. |
| Signed-out production TUI exited before showing login | Do not call catalog-validating model setters before authentication. Reconcile the account preferences against the catalog after login, before persisting the new session. A production-runner PTY test reaches login without a credential or account database; a local bootstrap test verifies preference reconciliation. |
| An inspector could obscure an incoming agent approval/question | Render foreground interactions last, matching keyboard priority. Escape on the visible interaction still cancels the task. Render tests cover both approval and question cards above the usage inspector. |

## Desktop observations

The first production launch reproduced `authentication required; sign in to your
Axiom account` and exited before showing login. After rebuilding with the
startup correction, the TUI displayed its sign-in overlay and successfully
requested a short-lived authorization from the deployed service.

The system-default Zen browser could not open its existing profile. Its error
dialog was dismissed without terminating the existing browser. The same native
authorization link was opened in an isolated Firefox profile, reaching the
hosted sign-in page. No passwords, tokens or authorization URLs are recorded here.

## Validation and remaining gate

`cargo fmt --all -- --check`, `git diff --check` and strict Clippy for all CLI
targets/features passed. The CLI library suite passed 345 tests (two standard
ignored tests), ACP transcripts passed 31 and PTY tests passed 20: **396 passed**.
These include real local filesystem/tool fixtures,
approval/question handling, cancellation and resume; deterministic runner tests
are not live model inference.

Live provider inference and end-to-end agent mode remain **pending account
authentication**. The native CLI was signed out; no credentials were bypassed
and no live provider request was issued. A scratch workspace was prepared with
an intentionally faulty Decimal invoice calculator and three unit tests. After
sign-in, the live acceptance task is to inspect and repair that calculator,
approve bounded tool operations, run the tests, inspect usage/security, exercise
steering and cancellation, and verify the resulting local files. Until those
steps are completed, this report does not certify the deployed backend or live
agent mode.
