AxiomAI combines Trusted Execution Environment (TEE) verification with end-to-end encryption for model messages. In Axiom Desktop, the app on the user's device builds each request, checks hardware-backed attestation from the AI provider's protected server environment, and encrypts the conversation to a key bound to that verified environment before sending it. Replies are authenticated to the verified environment and the request. Attestation ties the environment's running software to inspectable source and build provenance.

The privacy badge in the message composer describes the selected model's server environment and encrypted connection. It shows "TEE verified", "Verifying TEE", or the current report state. Model messages are decrypted only inside the verified environments to generate replies. AxiomAI's account servers and infrastructure operators relay encrypted model traffic and cannot read the conversation on this verified path. This provides inspectable cryptographic evidence of the software handling messages and prevents operators from harvesting readable conversations for surveillance or training, instead of asking users to rely solely on a "no logs" promise. The privacy assurance comes from the verified code and encrypted handling, not encryption alone.

Conversations are stored locally on the user's device, and AxiomAI does not keep a readable copy. Local history is protected by the operating system account and the device's disk protections rather than separate app-level encryption.

Some features have separate privacy boundaries. When Web is enabled, search queries go through Axiom's search service to an external search provider and web pages are fetched from the device; neither is end-to-end encrypted, although results are encrypted when included in later model requests. Agent mode tools and connected MCP services run on the user's device or on services the user configured, outside the model's protected environment.
