AxiomAI combines Trusted Execution Environment (TEE) verification with end-to-end encryption for model messages. In Axiom Desktop, the app on the user's device builds each request, checks hardware-backed attestation from the AI provider's protected server environment, and encrypts the conversation to a key bound to that verified environment before sending it. Replies are authenticated to the verified environment and the request. Attestation ties the environment's running software to inspectable source and build provenance.

The privacy badge in the message composer describes the selected model's server environment and encrypted connection. It shows "TEE verified", "Verifying TEE", or the current report state. Clicking it opens Environment attestation, which lists the hardware, encryption-key, freshness and source-provenance checks. Model messages are decrypted only inside the verified environments to generate replies. AxiomAI's account servers and infrastructure operators relay encrypted model traffic and cannot read the conversation on this verified path. This provides inspectable cryptographic evidence of the software handling messages and prevents operators from harvesting readable conversations for surveillance or training, instead of asking users to rely solely on a "no logs" promise. The privacy assurance comes from the verified code and encrypted handling, not encryption alone.

Conversations are stored locally on the user's device, and AxiomAI does not keep a readable copy. The local chat database is encrypted with SQLCipher; managed image and file payloads are authenticated encrypted files outside the database. Independent local storage keys are protected by the operating system credential store. Desktop drafts and queued messages use the same encrypted native storage. Explicit exports, image saves, clipboard contents and Agent workspace files have their own local privacy boundaries.

Some features have separate privacy boundaries. When Web is enabled, search queries go through Axiom's search service to an external search provider and web pages are fetched from the device; neither is end-to-end encrypted, although results are encrypted when included in later model requests. Agent mode tools and connected MCP services run on the user's device or on services the user configured, outside the model's protected environment.
